# 🤖 AI QA Assistant

Расширение для Chrome, которое запускает тестовые сценарии на реальной веб-странице, описанные обычным текстом на русском или английском. Без Selenium, без Playwright, без облака — всё работает в самом браузере.

```
Нажми кнопку "Авторизоваться"
Введи в поле "Имя пользователя" текст "testuser"
Нажми Enter
Результат: Добро пожаловать, testuser
```

**Текущая версия: 0.1** — детерминированное ядро. Семантическая модель пока не подключена: резолвер цели работает на точных совпадениях, префиксах и Jaccard по токенам. Модель появится в следующих версиях как ранжировщик, а не как замена эвристикам.

## Возможности

### Действия над страницей

| Действие | Что делает | Пример |
|---|---|---|
| **Клик** | Левый клик по элементу | `Нажми кнопку "Отправить"` |
| **Правый клик** | Полная эмуляция pointer + mouse + `contextmenu` | `Правый клик по "Избранное"` |
| **Ввод** | Запись в `<input>`, `<textarea>`, `[contenteditable]` | `Введи в поле "Email" текст "test@test.ru"` |
| **Выбор** | Выбор опции в `<select>` | `Выбери "Москва"` |
| **Нажатие клавиши** | Enter, Tab, Escape, стрелки, F1–F12, буквы, комбинации | `Нажми Ctrl+Enter` |
| **Скролл** | Прокрутка окна или элемента | `Прокрути вниз на 500` |
| **Пауза** | Ожидание с обратным отсчётом | `Подожди 3 секунды` |
| **Проверка** | 12 видов структурных и текстовых проверок | `Проверь, что URL содержит "/chat"` |

### Ожидаемый результат

Строка `Результат: …` (а также `Ожидаемый результат:`, `Result:`, `Then:`) привязывается к предыдущему действию и автоматически проверяется после него:

```
Введи в поле "Message" текст "Привет"
Нажми Enter
Результат: Привет
```

### Подсветка

Найденный элемент подсвечивается фиолетовым контуром. Через 2 секунды подсветка плавно затухает за 500 мс. Это даёт визуальную обратную связь: куда именно попал матч.

## Установка

1. Скачайте файлы расширения в отдельную папку.
2. Откройте `chrome://extensions/`.
3. Включите **Режим разработчика** (тумблер в правом верхнем углу).
4. Нажмите **Загрузить распакованное расширение**.
5. Выберите папку с расширением.

Иконка появится на панели расширений. Кликните по ней → откроется боковая панель (side panel).

**Требования:**
- Chrome **114+** (раньше side panel API не существует)
- Никаких внешних подключений: модель, если появится, работает локально

## Быстрый старт

1. Откройте любую страницу, с которой хотите работать.
2. Кликните иконку расширения → откроется боковая панель.
3. Введите сценарий в текстовое поле.
4. Нажмите **▶ Запустить**.

Пример сценария:

```
Кликни по "Любовь Бабанова"
Подожди 2 секунды
Введи в поле "Message" текст "Привет!"
Нажми Enter
Результат: Привет
```

Карточки шагов появляются справа. Зелёная — успех, красная — ошибка с указанием причины, жёлтая — шаг выполняется.

## Синтаксис сценария

### Общие правила

- **Один шаг — одна строка.**
- Нумерация в начале строки игнорируется: `1. Нажми Enter` = `Нажми Enter`.
- Русский и английский равноправны.
- Регистр не важен.
- Кавычки: `"…"`, `'…'`, `«…»`, `“…”` — любые.
- Пустые строки пропускаются.

### Клик

```
Нажми кнопку "Войти"
Кликни по "Любовь Бабанова"
Кликни "Send message"
Нажми на кнопку Отправить
Открой ссылку "Помощь"
Перейди по ссылке "Настройки"
Click "Sign in"
```

Синонимы: `нажми`, `нажать`, `кликни`, `кликнуть`, `клик`, `тыкни`, `ткни`, `перейди`, `перейти`, `открой`, `открыть`, `click`, `tap`, `press`, `open`, `go to`, `visit`.

### Правый клик

```
Правый клик по "Избранное"
Клик правой кнопкой по "Файл"
ПКМ "Строка"
Контекстное меню "Заметка"
Right click on "Favorite"
Context menu "Item"
```

Открывает контекстное меню. После него пункты меню становятся видимыми элементами, и следующий шаг `Кликни "Read all"` их найдёт.

### Ввод текста

```
Введи в поле "Email" текст "test@test.ru"
Введи в поле "Message" "Привет"
Заполни поле "Имя пользователя" значением "admin"

Напиши "admin" в поле "Логин"
Вставь в поле "Комментарий" текст "Готово"

```

Синонимы глаголов: `введи`, `ввести`, `напиши`, `написать`, `заполни`, `заполнить`, `вставь`, `вставить`, `input`, `type`, `fill`, `enter`.

Маркеры значения: `текст`, `значение`, `сообщение`, `value`, `text`. Если маркера нет — значение берётся из вторых кавычек, либо из последнего слова, если кавычек нет.

### Выбор из списка

```
Выбери "Москва"
Выбери город "Санкт-Петербург"
Отметь "Согласен с условиями"
Select "Option 2"
```

**Ограничение:** работает для нативных `<select>`. Кастомные селекты (React-Select, MUI) пока только открываются, но не выбирают опцию — это в планах на следующую версию.

### Нажатие клавиш

```
Нажми Enter
Нажми клавишу Tab
Жми Escape
Нажми Ctrl+Enter
Нажми Shift+Tab
Нажми Backspace
Нажми стрелку вниз
Press Enter

```

**Поддерживаемые клавиши:**
- `Enter`, `Tab`, `Escape`/`Esc`, `Backspace`, `Delete`/`Del`, `Space`
- `ArrowUp`/`Up`, `ArrowDown`/`Down`, `ArrowLeft`/`Left`, `ArrowRight`/`Right`
- `Home`, `End`, `PageUp`, `PageDown`
- `F1` – `F12`
- Любая буква или цифра: `A`, `z`, `5`
- Модификаторы: `Ctrl` (или `Control`), `Alt`, `Shift`, `Meta` (или `Cmd`, `Win`, `Super`) в комбинации через `+`

**Куда летит нажатие:**
- Если у элемента есть фокус — в текущий сфокусированный элемент.
- Если ничего не сфокусировано — в `document.body`.

```
Прокрути вниз
Прокрути вверх на 500
Проскролль до конца
Скролл в самый верх
Прокрути на 300
Прокрути до "Любовь Бабанова"

```

Направления: `вниз`, `вверх`, `top`/`верх`/`в начало` (к началу страницы), `bottom`/`низ`/`до конца` (к концу страницы). Опционально — `на N` (пикселей). Опционально — `до "Текст"` для скролла до конкретного элемента.

### Пауза


Карточка шага показывает обратный отсчёт: «Осталось 2.7 сек». Кнопка **Отмена** прерывает паузу.

## Проверки

Строка начинается с `Проверь`, `Проверить`, `Убедись`, `Убедиться`, `Verify`, `Check`, `Assert`, `Expect`. Опционально — `, что` после глагола.

### Проверка текста

```
Проверь, что на странице есть "Спасибо за заявку"
Проверь "Добро пожаловать"
Проверь, что текст содержит "успешно"
```

Ищет по `document.body.innerText`. Сравнение точное и по токенам (≥70% слов должны найтись).

### Проверка URL

```
Проверь, что URL содержит "/login"
Проверь, что адрес страницы содержит "chat"
Проверь, что URL равен "https://example.com/"
```

### Проверка заголовка

```
Проверь, что заголовок содержит "DeepSeek"
Проверь, что title содержит "Chat"
```

### Проверка элемента

```
Проверь, что "Модальное окно" видимо
Проверь, что "Спасибо" скрыто
Проверь, что "Кнопка Войти" существует
Проверь, что "Уведомление" не существует
Проверь, что "Кнопка Отправить" активна
Проверь, что "Кнопка Отправить" неактивна
```

### Проверка значения поля

```
Проверь, что поле "Email" пусто
Проверь, что поле "Email" содержит "@"
Проверь, что поле "Message" равно "Привет"
```

Работает для `<input>`, `<textarea>`, `<select>`, `[contenteditable]`.

## Как работает резолвер

Каждая цель (например, `"Отправить"`) сопоставляется со всеми интерактивными элементами страницы. Оценка идёт по каскаду:

| Условие | Score |
|---|---|
| Точное совпадение после нормализации | 1.00 |
| Текст элемента начинается с цели | 0.95 |
| Текст содержит цель | 0.90 |
| Цель содержит текст элемента (и он ≥3 симв.) | 0.75 |
| Jaccard по токенам (словам) × 0.85 | до 0.85 |
| Элемент перекрыт другим | ×0.7 |

**Порог:** 0.55. Ниже — «цель не найдена».

**Неоднозначность:** если разница между первым и вторым кандидатом < 0.05 и лучший score < 0.9 — расширение останавливается и показывает обоих кандидатов. Лучше ошибка, чем угадывание.

### Что попадает в «подпись» элемента

- `aria-label`
- `<label for="…">` или обёртка `<label>`
- `placeholder`, `data-placeholder`, `aria-placeholder`
- `title`, `alt`
- Видимый текст (`innerText`)

Все части нормализуются: нижний регистр, схлопнутые пробелы, кавычки убраны, `\u00a0` → пробел.

### Какие элементы видит резолвер

`button`, `a[href]`, `input` (кроме `hidden`), `textarea`, `select`, `[role=button|link|textbox|combobox|menuitem|menuitemcheckbox|menuitemradio|option|tab]`, `[contenteditable]`.

Отсеиваются: невидимые (`checkVisibility`), без текста в подписи, `disabled` при выполнении действия.

## Как работает ввод в rich-редакторы

Telegram, DeepSeek и другие SPA используют contenteditable, построенные на Lexical / ProseMirror / Slate. Эти редакторы хранят текст в модели и рендерят эмодзи как пустые декораторы. Простой `element.textContent = value` или `execCommand` их ломает (вставка дублируется, эмодзи теряются).

Расширение делает так:

1. Выделяет текущее содержимое.
2. Отправляет синтетическое `beforeinput` — редактор сам решает, как вставить текст.
3. Если через 120 мс текста нет — отправляет синтетическое `paste` с `DataTransfer`.
4. Читает `textContent` и проверяет: probe (первые 15 символов значения) должен найтись **ровно один раз**.
5. Сравнение устойчиво к эмодзи: обе стороны проходят через `stripEmoji`, поэтому декораторные эмодзи не мешают.

Если сработало дважды — ошибка «редактор вставил текст N раз». Если ноль — «редактор не принял текст».

## Архитектура

```
┌─────────────────┐       ┌──────────────────┐       ┌──────────────────┐
│   Side panel    │──────▶│   Background     │──────▶│  Content script  │
│ (парсер, UI,    │       │ (релей + инъекция│       │ (резолвер DOM,   │
│  оркестратор)   │◀──────│  content script) │◀──────│  действия, чеки) │
└─────────────────┘       └──────────────────┘       └──────────────────┘
```

**`sidepanel.html` / `sidepanel.js`** — интерфейс, парсер сценария, раннер шагов, транспорт к background.

**`background.js`** — тонкий релей. Принимает `TAB_CALL`, проверяет, что content script инжектирован (через `PING`), если нет — инжектит через `chrome.scripting.executeScript`. Проксирует метод к вкладке.

**`content_script.js`** — всё, что касается DOM: `DESCRIBE` (список интерактивных элементов с подписями), `PERFORM` (клик, ввод, выбор, клавиша), `SCROLL`, `CHECK_ELEMENT`, `HIGHLIGHT`, `SNAPSHOT`, `WAIT_STABLE`.

**`manifest.json`** — MV3, минимальные разрешения (`sidePanel`, `scripting`), `host_permissions: <all_urls>`, content script `run_at: document_idle`.

## Транспорт и надёжность

- **Fallback-инъекция.** Если content script не загружен (расширение перезагружено, вкладка была открыта раньше) — background инжектит его автоматически через `chrome.scripting`.
- **Запрет на служебные страницы.** На `chrome://`, `edge://`, `about:` расширение останавливается с внятной ошибкой.
- **Ожидание стабилизации DOM.** После каждого действия — `MutationObserver` с окном тишины 250 мс и жёстким потолком 4 с. Никаких фиксированных `delay(800)`.
- **Отмена.** Кнопка **Отмена** в панели прерывает прогон между шагами и во время пауз.
- **Сверка фактического значения.** После `input` читаем значение обратно. Если React/Vue откатил — ошибка, а не тихое «Выполнено».

## Известные ограничения

Осознанные на текущей версии:

- **Нет iframe.** `all_frames: false`. Элементы внутри вложенных фреймов (капча, оплата, встроенные виджеты) невидимы.
- **Нет shadow DOM.** Веб-компоненты не проходятся.
- **Нет hover, drag&drop, загрузки файлов.**
- **Кастомные селекты (React-Select, MUI) не выбирают опцию** — только открываются кликом.
- **`Проверь, что текст есть` ищет по всему `body`.** Не отличает текст, который был на странице до действия, от появившегося после. Это частая причина ложных проходов.
- **Синтетический Enter не вставит перевод строки в пустую `<textarea>`** без обработчика. В чатах и формах, где на Enter висит отправка, работает нормально.
- **Скролл работает с окном и обычным overflow.** Виртуальные списки (react-window, react-virtualized) требуют прямого управления `scrollTop`.
- **Только Chrome 114+.**
- **Нет скриншотов и экспорта отчёта.**

## Roadmap

По убыванию приоритета:

1. **Кастомные селекты.** Открытие + поиск опции в появившемся DOM + клик.
2. **Проверка «появилось после действия».** Снимать snapshot `innerText` до шага, проверять разницу.
3. **iframe.** Через `all_frames: true` + реестр на каждый фрейм.
4. **Скриншоты на каждом шаге** через `chrome.tabs.captureVisibleTab`.
5. **Hover и drag&drop.**
6. **Семантическая модель** (Xenova/paraphrase-multilingual-MiniLM) как ранжировщик топа кандидатов. Не заменяет эвристики, а помогает при неоднозначностях.
7. **Запись сценария** через перехват реальных действий пользователя.
